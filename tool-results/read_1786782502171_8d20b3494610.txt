    71→    71→2. **`src/app/api/digital-products/verify/route.ts`** — POST handler for payment verification
    72→    72→   - Zod validation: `{ orderId, razorpayOrderId, razorpayPaymentId, razorpaySignature }`
    73→    73→   - Looks up local order; returns 404 if not found
    74→    74→   - Verifies `razorpayOrderId` matches the one on the local order (mismatch → 400)
    75→    75→   - Verifies payment signature via `verifyPaymentSignature` (HMAC-SHA256); invalid → 400
    76→    76→   - Updates order: status → PAID, sets `razorpayPaymentId`, `razorpaySignature`, `paidAt`
    77→    77→   - Calls `fulfilOrder` (generates download token + sends email; idempotent)
    78→    78→   - Returns `{ success: true, orderId }`
    79→    79→
    80→    80→3. **`src/app/api/digital-products/order-status/route.ts`** — GET handler for order status
    81→    81→   - Gets `orderId` from query params; returns 400 if missing
    82→    82→   - Looks up order in database; returns 404 if not found
    83→    83→   - If order is PAID and `fulfilmentSentAt` is set, generates download URL via `generateDownloadToken`
    84→    84→   - Download URL: `/api/digital-products/download/[token]`
    85→    85→   - Returns `{ status, productName, customerEmail, downloadUrl? }`; product name from config
    86→    86→
    87→    87→4. **`src/app/api/digital-products/webhook/razorpay/route.ts`** — POST handler for Razorpay webhooks
    88→    88→   - Gets raw body as text (does NOT JSON parse before signature verification)
    89→    89→   - Gets `X-Razorpay-Signature` header; verifies via `verifyWebhookSignature`
    90→    90→   - Invalid signature → 400
    91→    91→   - Parses JSON body after verification
    92→    92→   - Idempotency: checks `paymentWebhookEvent.findUnique` on `eventId`; returns 200 if duplicate
    93→    93→   - Stores event in `paymentWebhookEvent` table
    94→    94→   - Handles event types using `after()` from `next/server` for non-blocking work:
    95→    95→     - `payment.captured`: finds order by `razorpay_order_id`, marks PAID if not already, triggers fulfilment
    96→    96→     - `payment.failed`: finds order, marks FAILED
    97→    97→     - `refund.created` / `refund.processed`: finds order, marks REFUNDED, sets `refundedAt`
    98→    98→   - Returns 200 promptly (doesn't hold response for email sending)
    99→    99→
   100→   100→5. **`src/app/api/digital-products/download/[token]/route.ts`** — GET handler for secure file download
   101→   101→   - Gets token from route params
   102→   102→   - Verifies token via `verifyDownloadToken` (HMAC-SHA256 signature + expiry check); invalid/expired → 403
   103→   103→   - Looks up order by `orderId` from token payload; not found → 403
   104→   104→   - Verifies order status is PAID; not paid → 403
   105→   105→   - Verifies product entitlement: `productId` from token matches order's `productId`; mismatch → 403
   106→   106→   - Increments `downloadCount` and sets `lastDownloadAt` on order
   107→   107→   - Gets product file via `getSecureProductFile`; not found → 404
   108→   108→   - Streams file as Response with headers:
   109→   109→     - `Content-Type: application/zip`
   110→   110→     - `Content-Disposition: attachment; filename="[product-name].zip"`
   111→   111→     - `Cache-Control: no-store, no-cache, must-revalidate`
   112→   112→   - Converts Node.js ReadStream to Web ReadableStream for streaming
   113→   113→
   114→   114→### Security Measures
   115→   115→- Server-owned pricing: client never sends amount/price/discount
   116→   116→- Zod validation on all inputs
   117→   117→- HMAC-SHA256 signature verification for payments, webhooks, and download tokens
   118→   118→- Webhook idempotency via event deduplication
   119→   119→- Download token expiry (7 days) and product entitlement verification
   120→   120→- `after()` for non-blocking fulfilment work in webhook handler
   121→   121→- No internal error details exposed to client (generic error messages)
   122→   122→- Path traversal protection inherited from product-storage.ts
   123→   123→- Cache-Control headers prevent download URL caching
